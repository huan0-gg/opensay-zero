## 1. 意图与为什么

PRD v2.0 的产品定位是「口语 A2–B2 的成人，8 周在高频场景独立交流」，并明确把 A1 以下 22% 的零基础挡在测评之外（AC-1-05：「本产品从 A2 起步」）。

本设计服务的是另一个人：**一个真正从零开始、每天只有 10 分钟的成人学习者，4 周后要能在咖啡店完成一次「问价 → 选款 → 付款」的简单对话。**

这不是把 PRD 的难度调低一档，而是把起点前移：

- 从「有 A2 底子、只是开不了口」前移到「几乎不会说，也听不懂」；
- 从「8 周、18 个场景」收缩到「4 周、5 个场景」；
- 从「LLM 自由生成对话」改为「作者编写的状态机对话」，保证零基础用户不会被生成长句淹没，也保证离线、可测、可审。
- 从「WIT ≥ 30 轮/周」改为「零基础可判定的独立轮次」：一轮 = 非跟读、非提示、≥ 2 个词、能构成一个意图。

PRD 的五个核心机制保留：4 必说 + 8 能懂、三天闭环、首轮不打断、复盘只给 3 条修正、到期句块在对话里复现。

一句话：**用 PRD 的机制，服务 PRD 排除掉的那 22%，用一个能演出来的咖啡店片段作为验收锚点。**

## 2. 用户与成功画面

### 2.1 用户

- 成人，中文母语，英语接近零基础：能认出少量单词，基本没有开口经验。
- 每天可投入 10 分钟，连续 4 周（允许每周补签 1 次）。
- 学习动机是「马上要用」：旅行、咖啡店、超市、问路、简单点餐。
- 设备：手机为主，浏览器打开即用；可能没有稳定网络。

### 2.2 一个月后的成功画面（验收锚点）

咖啡店，学生排在队尾，手里没有翻译 App：

> 店员：Hi, what can I get for you?
> 学生：How much is this coffee?
> 店员：It's four fifty.
> 学生：Okay, I'll take this one.
> 店员：For here or to go?
> 学生：To go, please.
> 店员：Card or cash?
> 学生：Card, please.
> 店员：Here you are.
> 学生：Thank you.

硬性判据：

1. 学生主动开口 ≥ 5 轮，其中 ≥ 4 轮不是跟读、不是点提示；
2. 用出 ≥ 3 个本场景「必说」句块；
3. 价格/杯型/付款至少一处被换成没练过的说法（如 four eighty、large、cash），仍能接住；
4. 全程没有退回中文或长时间沉默（单次沉默 < 10 秒）。

## 3. 目标 / 非目标 / 反目标

### 3.1 目标

- G1：20 次 10 分钟会话（4 周 × 5 天）内，完成 5 个场景的三天闭环。
- G2：咖啡店场景在 D3 与第 4 周终测中，达到 2.2 的硬性判据。
- G3：每次会话 ≤ 12 分钟自动收束；每天只有 1 个主任务。
- G4：零基础用户第一次打开，3 分钟内能说出第一句英文。
- G5：进度、录音、句块本在本机持久化，刷新/重启不丢。
- G6：核心机制（提示、状态机、复习、复盘、计量）有自动化测试覆盖。

### 3.2 非目标（这一版不做）

- 18 个场景、P1 的 12 个场景；
- F6 出行实时辅助、F8 内容后台、真人陪练；
- 账号、云同步、订阅与支付；
- LLM 实时生成对话（v1 用作者脚本 + 意图匹配）；
- 音素级发音评分、口型视频；
- 雅思/托福、少儿、语法系统课、社区/排行榜；
- CEFR 正式认证（只做内部 6 档估计，且不作为卖点）。

### 3.3 反目标（技术上成功也算失败）

- 用户觉得自己在「被考试」：红叉、分数、排名、"不及格"。
- 用户背会了一段固定台词，换一个价格就接不住。
- 用户必须先会打字/会读英文才能开始。
- 一次练习超过 12 分钟，或变成需要意志力完成的作业。
- 进步是假的：点提示、跟读、乱说都算「说对」。
- 语音不可用时整个产品卡死，没有降级路径。

## 4. 约束

- **形态**：浏览器 Web 应用，手机优先，桌面可用；首次加载后不依赖网络（语音识别本身可能依赖浏览器服务，见 9.3）。
- **数据**：全部存本机（localStorage + IndexedDB），无后端、无账号、无密钥。
- **语言**：中文界面 + 英文学习内容；所有解释、纠错理由用中文。
- **语音**：浏览器 `speechSynthesis`（朗读）与 `SpeechRecognition`（识别）；识别不可用时必须能落文本/点选。
- **内容**：5 个场景、每场景 4 必说 + 8 能懂、每场景 3 天；美式英语，A1 词汇，价格用数字与美元。
- **合规**：不采集通讯录/位置；录音仅本机；提供一键删除与导出；不面向 12 岁以下。
- **可访问性**：键盘可达、对比度 ≥ 4.5:1、尊重 `prefers-reduced-motion`、所有按钮有可读标签。

## 5. 已由用户拍板的决定

1. 目标用户是零基础（A1 以下），不是 PRD 的 A2–B2。
2. 成功周期是 1 个月，成功画面是咖啡店问价—选款—付款。
3. 第一版范围：4 周路径 + 咖啡店锚点 + 4 个同难度生存场景。
4. 形态交给构建者定：浏览器应用。

## 6. 我拍板的决定（构建者，可推翻）

这些不是用户说的，是我为了让事情成立做的选择；用户可在批准前推翻。

- D1：**对话用作者编写的状态机 + 意图匹配，不用 LLM。** 零基础用户经不起生成长句；离线与可测也要求确定性。
- D2：**首周默认「英文 + 中文」字幕，第 2 周起引导切到纯英文。** PRD 默认纯英文，对零基础太陡。
- D3：**发音反馈只到词级 + 作者写的发音提示**，不做音素评分；反馈永不使用禁用词。
- D4：**不做账号与云同步**，进度只在本机；提供 JSON 导出/导入作为备份。
- D5：**5 个场景**：咖啡店点单、自我介绍、超市结账、问路、餐厅点餐。
- D6：**测评不作为门槛**，结果只用于给基线录音与鼓励，不拦截任何用户。
- D7：**界面用暖色、低刺激的视觉**，不用红色表示错误、不用连胜惩罚。
- D8：**技术栈 Vite + React + TypeScript**，测试用 Vitest + Testing Library + Playwright。

## 7. 产品机制

### 7.1 四周路径（20 次会话）

| 周 | 主题 | 场景与节奏 | 周末应该能做到 |
|:--|:--|:--|:--|
| W1 | 开口第一句 | 咖啡店 D1–D3；自我介绍 D1–D2 | 点一杯咖啡的前半程；说出名字与来自哪里 |
| W2 | 买东西 | 自我介绍 D3；超市 D1–D3；咖啡店变体 | 问价、要袋子、刷卡；咖啡店换价格也能接 |
| W3 | 出门 | 问路 D1–D3；餐厅 D1–D2 | 问路并听懂左右/远近；点餐与忌口 |
| W4 | 串起来 | 餐厅 D3；综合 D1–D3；咖啡店终测；庆祝 | 无提示完成咖啡店全流程；迁移到新价格/杯型 |

每天只有 1 个主任务；已完成当天任务后，首页展示「今天已完成」与可选加练，不重复推主任务。

### 7.2 场景、句块与三天闭环

每个场景 12 个句块：**4 必说 + 8 能懂**。

- 必说：要求独立说出，经过「听 → 跟读 → 在对话里用一次」三步才算学会。
- 能懂：只要求「听 + 选对义」，不要求出声。
- 每个场景另有 3 条**全局兜底句**（没听懂 / 说慢点 / 再来一次），从第 1 天起常驻，不占 4 条必说的名额。

三天闭环：

- **D1 学**：4 必说中的 2 条 + 4 能懂；NPC 带 2 轮示范（可跳过）。
- **D2 复现**：D1 的 2 条 + 新的 2 条必说；对话里必须真的用出 D1 的句块。
- **D3 全开放**：不给示范，加入 1 个变化（价格/杯型/付款方式），完成后解锁「能说」徽章，并给一个现实任务（如「明天真的去点一杯，回来录音」）。

### 7.3 一次 10 分钟：3 + 5 + 2

1. **复习 3 分钟**：最多 6 个到期句块，每个「听 → 说」；连续 2 次失败降级为跟读 + 慢速示范，不判失败。
2. **场景 5 分钟**：进入当天对话；首轮不打断；沉默 3 秒出兜底浮层；累计 12 分钟自动收束。
3. **复盘 2 分钟**：最多 3 条修正（你说的 → 更自然 → 为什么）、1 段最佳录音、「今天说对 N 句」、明天练什么。

### 7.4 对话引擎

**结构**：场景 = 有序节点；每个节点 = NPC 台词（2 个变体）+ 期待意图 + 通过条件 + 未知/跑题处理。

- 必经节点不可跳过；用户说了下一节点的话，NPC 也先把当前节点走完（例如先回答价格，再问杯型）。
- 意图匹配：关键词/短语命中 + 句块相似度（归一化编辑距离）；低于阈值视为「没听懂」，不判错。
- 用户连续 2 轮说与场景无关的话 → NPC 用一句话自然拉回（「我们先点单吧，你想喝什么？」），不批评。
- 连续 3 次提示或跟读 → 本轮标记为 assisted，不计独立轮次，但流程继续。
- 敏感话题（医疗/法律/投资）→ 固定话术「这个我建议你咨询专业人士」，不展开。
- 变体：价格在 3.80–5.20 之间按会话种子取一个；杯型、冷热、付款方式各有 2 种问法，避免背台词。

**独立轮次判定**（本机版 WIT）：

同时满足才计 1 轮：用户主动发起；未点提示；非逐字跟读；识别文本 ≥ 2 个词；构成一个可映射的意图；识别置信度 ≥ 0.6（文本输入路径视为满足）。

### 7.5 测评（可跳过）

6 道题，约 3 分钟：3 道听辨选择、2 道跟读、1 道开放回答（What's your name?）。

- 输出：基线录音 1 段、能听懂的常用句数、「你已经能说 X 句」、从 W1D1 开始。
- 不出现分数、等级、错误数；不因结果拦截任何人。
- 中途退出可续；14 天内重复测评会提示「短期变化可能不明显」，且不覆盖基线。

### 7.6 复习

- 句块状态 0–5，间隔 1 / 3 / 7 / 15 / 30 天。
- 通过 → 进一档；失败 → 退一档并顺延 1 天；连续 2 次失败 → 第 3 次给首词提示 + 慢速示范。
- 到期句块优先在当天对话的「复习车道」里复现；复现失败才回落到跟读。

### 7.7 反馈与措辞

- 对话中不打断、不提示错误。
- 复盘最多 3 条，按「是否影响理解」排序；每条三段式：你说的 → 更自然的说法 → 为什么（一句中文）。
- 词级发音提示只给可执行动作，例如「th：舌尖轻轻放在上下齿之间」。
- 禁用词表（命中即测试失败）：很差、太差、糟糕、错误、你说错了、需要加强、多练练、不及格、不达标、口音重。

### 7.8 进步可视化

- 首页：连续天数、本周独立轮次、今天说对 N 句。
- 「能说清单」：已完成场景、已掌握必说句块、首次独立完成日期，用「能做到」表述。
- 场景徽章：完成 D3 解锁；不做排名、不做用户对比。
- 4 周报告：文本对比（句长、句块命中、提示次数）+ 本机录音回放（本机存储，无需授权）。

### 7.9 状态与数据

- 首次进入：欢迎页（一句价值 + 开始测评 / 直接开始）。
- 未完成测评：首页保留入口卡片，每天最多提示 1 次。
- 数据：`localStorage` 存进度与设置；IndexedDB 存录音（30 天滚动删除）。
- 导出/导入 JSON；重置有二次确认。

## 9. 技术方案

### 9.1 栈

- Vite + React 19 + TypeScript（严格模式）
- 路由：react-router-dom
- 状态：Zustand（含 persist 中间件，或自写 storage 适配）
- 样式：CSS Modules + design tokens（不引入 UI 框架）
- 校验：Zod（持久化 schema 与内容 schema）
- 测试：Vitest + @testing-library/react + Playwright
- 音频：MediaRecorder + IndexedDB（idb-keyval）

### 9.2 模块划分

```text
src/
├─ app/            路由、布局、全局样式
├─ domain/         纯逻辑：scheduler、turn-filter、intent-matcher、node-guard
├─ content/        5 个场景的 JSON/TS 数据 + 内容校验
├─ features/
│  ├─ assessment/
│  ├─ session/     review → dialogue → recap 状态机
│  ├─ scenes/
│  ├─ chunks/
│  └─ profile/
├─ services/       speech（TTS/ASR）、recorder、storage、telemetry(local)
└─ ui/             通用组件（Button、Card、Sheet、Progress…）
```

### 9.3 语音与降级

- TTS：优先 `en-US` 女声，语速 0.8（可调 0.8/1.0/1.2）；播放中检测用户发声则 300ms 内停止。
- ASR：`webkitSpeechRecognition`，`lang=en-US`，单轮 ≤ 12 秒；超时/报错/无权限 → 文本输入 + 点选回答。
- 识别不可用时，对话仍可完成：NPC 台词走字幕，用户从 2–3 个候选句里点选并跟读，计为 assisted。
- 发音反馈：识别文本对齐目标词；未命中的词给作者提示；无识别则只做「听示范 + 自录 + 自评」。

### 9.4 持久化

```ts
type Progress = {
  schemaVersion: 1
  assessment?: { completedAt: string; heard: number; baselineRecordingId?: string }
  chunks: Record<string, { stage: number; dueAt: string; lapses: number; lastResult?: 'pass' | 'fail' }>
  scenes: Record<string, { day: 1 | 2 | 3; completedDays: number[]; badge: boolean }>
  sessions: Array<{ id: string; date: string; sceneId: string; turns: number; independentTurns: number; minutes: number; hints: number; corrections: number }>
  streak: { current: number; longest: number; lastActiveDate?: string; freezesUsed: number }
  settings: { rate: 0.8 | 1 | 1.2; subtitles: 'en' | 'en-zh' | 'off'; sound: boolean }
}
```

- 迁移函数按 `schemaVersion` 顺序执行；非法数据回退到空状态并提示。
- 录音 key 带日期，30 天后清理；「删除我的录音」立即清空 IndexedDB。

### 9.5 可测性

- 对话引擎、调度器、轮次判定为纯函数，全部单测。
- 语音通过 `SpeechPort` 接口注入；测试用 FakeSpeech，E2E 用 `window.__opensayTest` 钩子注入脚本化识别结果。
- 内容校验测试：每个场景 4 必说、8 能懂、每个必经节点 ≥ 2 条分支、无死路、禁用词检查。

## 10. 内容规范

- 场景 JSON 字段：`id, title, domain, level, week, objectives, nodes[], chunks[], mission, badge`。
- 节点字段：`id, npc{en,zh,variants[]}, expect{intents[], chunks[]}, hints[2], onUnknown, onOffTopic, next, required`。
- 句块字段：`id, sceneId, tier, en, zh, variants[2], tip?, audioText`。
- 文案语气：短句、具体、不夸张；不承诺「30 天流利」；不出现「考试/及格/错误」。
- 价格与数字用阿拉伯数字 + 英文读法；避免俚语与地域性表达。
- 每个场景的 4 必说固定结构：1 条救场 + 2 条核心请求 + 1 条收尾/付款。

| 编号 | 验收标准 | 优先级 |
|:--|:--|:--|
| AC-Z-01 | 首次打开 3 分钟内可完成 1 轮「听示范 → 跟读 → 得到鼓励」，无需注册、无需读完说明 | P0 |
| AC-Z-02 | 首页只给 1 个主任务；完成后显示「今天已完成」与加练入口，不重复推送 | P0 |
| AC-Z-03 | 对话中沉默 3 秒出现 2 条可点兜底句；点击只播放与展示，不自动替用户说 | P0 |
| AC-Z-04 | 用户说话时 TTS 在 300ms 内停止；不打断用户 | P0 |
| AC-Z-05 | 单次会话到 12 分钟自动进入复盘，之后不能再追加轮次 | P0 |

## 12. 测试策略

- **单元**（Vitest）：调度器（1/3/7/15/30、失败降档、连续失败降级）、独立轮次过滤、意图匹配（命中/未命中/多意图）、节点守卫（不可跳过）、12 分钟收束、禁用词、存储迁移与损坏恢复。
- **组件**（Testing Library）：3 秒提示（fake timers）、复盘最多 3 条、麦克风拒绝降级、字幕切换、assisted 标记。
- **端到端**（Playwright，脚本化语音）：欢迎 → 跳过测评 → 咖啡店 D1 完整走完 → 刷新后进度仍在 → D3 徽章 → 12 分钟收束。浏览器优先用本机 Edge/Chrome，避免额外下载。
- **内容测试**：加载 5 个场景，跑 schema 校验 + 结构断言（4+8、分支、死路、禁用词）。
- **手工验收脚本**：见 11 与 2.2；用真实麦克风在 Edge 中完成一遍咖啡店 D1–D3。
- **完成定义**：`pnpm test`、`pnpm build`、`pnpm e2e` 全绿；手工脚本通过；无 P0 缺陷。

## 13. 风险与未解决

| 风险 | 影响 | 缓解 |
|:--|:--|:--|
| 浏览器 ASR 对中式口音识别差 | 用户说了却被判「没听清」 | 意图匹配放宽、关键词容错、文本/点选兜底、低置信不判错 |
| TTS 声音机械或缺失 | 零基础听不懂、体验差 | 选本机最佳 en-US 声、0.8 倍速、字幕始终可读 |
| 状态机对话显得死板 | 用户背台词，迁移失败 | 每节点 2 变体、D3 变化、终测换价格/杯型/付款 |
| 5 个场景不够撑一个月 | 第 3 周失去新鲜感 | 变体与复习车道、现实任务、第 4 周综合与终测 |
| 无后端导致无真实数据 | 无法验证留存/WIT | 本机记录 + JSON 导出；后续接后端再补 |
| 内容质量 | 学错表达 | 每场景 4+8 结构校验、禁用词、人工通读 |

未解决（需要用户在批准时确认）：

1. 产品名是否沿用「开口英语 OpenSay」。
2. 是否接受 v1 用作者脚本对话、不做 LLM 生成。
3. 是否接受「发音反馈只到词级」。
4. 是否接受首发只有 5 个场景（而非 PRD 的 18 个）。
